# Phase 4.1 Plan 09: Snapshot, versão e gate do contrato

Cada versão nova do contrato agora é o snapshot estruturado (formato 2) com o hash do snapshot, o link só sai com os dados do layout completos (`CONTRACT_INCOMPLETE` + query `contractReadiness`) e gerar o link cria versão nova quando a corrente é legada ou está desatualizada.

## O que foi feito

- **`contract-render.ts` reescrito**: `buildLiveSnapshotTx` monta o snapshot a partir de contrato, grupo, contratante, pacote, itens, parcelas e configurações efetivas (textos passados por `renderContractText`); `renderContractVersionTx` grava `snapshot`, `snapshotFormat: 2`, `textSha256 = snapshotHash` e atualiza `currentVersion` e `contractorClientId`; `refreshContractVersionTx` cria versão só se a corrente é formato 1 ou o hash vivo difere; `loadReadinessInputTx` alimenta `missingRequiredFields`.
- **GraphQL**: `contractReadiness(id)` (`ContractReadiness`/`ContractMissingField`) e `Contract.currentSnapshotFormat`.
- **`generateLink`**: depois de EDITABLE/ALREADY_ACCEPTED e antes de revogar tokens, aplica o gate e o refresh; o token aponta para a versão resultante.
- **Adendo do orquestrador (`uf_foro`)**: novo `estadoPorUf` (27 UFs, desconhecida volta crua) em `domain/`; o snapshot preenche `uf_foro` com o estado por extenso, então as disposições finais dizem "Estado de São Paulo". Teste de unidade cobre as 27 UFs, o fallback e a renderização da cláusula; a integração confere o snapshot gravado.
- **E2E existente**: `completeContractData(token, { groupId, brideClientId? })` em `support/phase4.ts` (cliente, horário do grupo preservando os demais campos, studio) chamado antes de "Gerar link de aceite".

## Migração preguiçosa D-18

Rascunhos/aguardando com versão legada (formato 1) ganham versão formato 2 quando: (1) são editados (`update` sempre renderiza); (2) se gera o link (`refreshContractVersionTx`); (3) no PDF do dono antes do aceite, por snapshot ao vivo não gravado (04.1-13). O backfill do 04.1-01 só revogou os links pendentes. Versões já gravadas nunca são alteradas.

## Deviations from Plan

[Rule 3 - Bloqueio] Specs existentes da fase 4 quebraram pelo gate** — `phase4-contracts-core`, `phase4-public-acceptance`, `phase4-contract-cancel` geravam link sem CPF/celular 2/horário/studio/pacote/sinal. Criados helpers `makeContractReady`, `completeStudioSettings` e `attachPackage` em `phase4-fixtures.ts` e ajustadas as expectativas: o hash do contrato aceito passa a ser lido da versão corrente; contagens de versão +1 porque vincular o pacote por SQL depois da criação gera versão no link; a asserção `sha256(texto) == hash` virou "64 hex" (hash agora é do snapshot).

**2. `versions` com `snapshotFormat` no view** — o view não expõe lista de versões, então só `currentSnapshotFormat` foi adicionado.
