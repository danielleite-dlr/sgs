## Armadilha de descoberta de testes — ler antes de escrever qualquer teste

`apps/backend/jest-integration.config.ts:7` usa:

```
testRegex: '.*\.spec\.ts$'
```

Isso exige um **ponto** literal antes de `spec.ts`. Consequência verificada empiricamente:

| Arquivo | Descoberto pelo Jest? |
|---|---|
| `members.e2e.spec.ts` | sim |
| `rls-isolation.spec.ts` | sim |
| `rbac.e2e-spec.ts` | **não** |
| `invitation.e2e-spec.ts` | **não** |
| `auth.e2e-spec.ts` | **não** |
| `full-auth-flow.e2e-spec.ts` | **não** |

Regras que decorrem disso:

1. **Todo arquivo novo usa PONTO:** `members-lifecycle.e2e.spec.ts`, nunca `-spec.ts`.
2. **Nunca cite `rbac.e2e-spec.ts` ou `invitation.e2e-spec.ts` como prova de não-regressão** — eles não rodam. Se esta fase precisa provar que o convite de 2 campos não regrediu, o caso tem que viver dentro de um arquivo que o Jest descobre.
3. **Não rode `pnpm test:e2e`** — o script aponta para `./test/jest-e2e.json`, que não existe no repositório. Falha na hora, independentemente do código.

Os 4 arquivos órfãos estão registrados como todo no `STATE.md`; corrigi-los está fora do escopo desta fase.
