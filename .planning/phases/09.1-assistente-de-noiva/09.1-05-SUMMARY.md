# Phase 09.1 Plan 05: Vínculo da assistente e bloqueio de agenda Summary

Vincular, trocar e remover a assistente da noiva pela API, com bloqueio `acompanhamento` de dia inteiro (fuso da org), candidatas livres/ocupadas com motivo, diária congelada no vínculo e a pendência exposta no `BridalGroup`.

## Contrato GraphQL final (para os planos 06 e 09)

`BridalGroup` ganhou:
- `assistantRequired: Boolean!` (elegível: noiva + estúdio + ativo + pacote com a flag)
- `assistantPending: Boolean!` (elegível, sem assistente, evento hoje/futuro, comanda do evento não fechada)
- `assistantMemberId: UUID`, `assistantName: String`
- `assistantDailyRate: String` (ex.: `"220.00"`; `null` para quem não é ADMIN/MANAGER)

`BridalGroupPayload` ganhou `warning: String` (hoje sempre `null` neste plano; reservado para o aviso de remoção por inelegibilidade, D-05).

```graphql
type BridalAssistantCandidate { memberId: UUID! displayName: String! available: Boolean! reason: String current: Boolean! }
Query:    bridalAssistantCandidates(groupId: UUID!): [BridalAssistantCandidate!]!   # BRIDAL_WRITE
Mutation: setBridalGroupAssistant(groupId: UUID!, memberId: UUID): BridalGroupPayload! # BRIDAL_WRITE; memberId null remove
```

Códigos de erro (`errors[].code`): `NOT_FOUND`, `ASSISTANT_NOT_ALLOWED`, `NOT_A_BRIDAL_ASSISTANT`, `EVENT_COMANDA_CLOSED`, `ASSISTANT_BUSY`. Na agenda: `TIME_BLOCKED` (agendamento sobre a assistente), `PROFESSIONAL_ESCORTING_BRIDE` (bloqueio manual no dia), `SYSTEM_BLOCK` (criar/apagar `acompanhamento` à mão).

Motivos das candidatas: "Já acompanha outra noiva neste dia", "Tem atendimento neste dia", "Bloqueio na agenda neste dia (<Tipo>)".

`clearAssistantTx(tx, orgId, actorId, groupId, 'ineligible')` está pronto para o plano que remove a assistente quando o grupo deixa de ser elegível (devolve `removedName` para montar o `warning`). Ainda NÃO é chamado em `updateBridalGroup`/cancelamento.
