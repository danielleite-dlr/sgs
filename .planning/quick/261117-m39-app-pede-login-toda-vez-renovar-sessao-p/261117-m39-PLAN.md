Contrato do backend (apps/backend/src/graphql/schema/auth.graphql):
- `refreshSession(input: RefreshInput!): AuthPayload!` — `@Public()`; `input RefreshInput { refreshToken: String! }`.
- `AuthService.refresh` faz try/catch: em falha devolve payload com `accessToken: null` e `errors: [{ code }]` (HTTP 200), não lança. `TokenService.rotateRefresh` revoga o token usado e, se um token já revogado for reapresentado, revoga a FAMÍLIA inteira (TOKEN_REUSE_DETECTED) — por isso o single-flight é obrigatório.

Store (auth.store.ts): `useAuthStore.getState()` → `{ accessToken, refreshToken, impersonating, platformSession, clearSession(), takePlatformStash(), updateAccessToken() }`; `useAuthStore.setState({ accessToken, refreshToken })`. Persistido em localStorage 'sgs-auth'.

Cadeia Apollo (client.ts): `from([errorLink, authLink, httpLink])` — o authLink lê o token do store a cada passagem, então `forward(operation)` depois da renovação já sai com o token novo.

test-setup.ts já instala um mock de localStorage (Map) em globalThis/window — chamar `localStorage.clear()` no beforeEach.

useAuth.logout chama só `clearSession()` (zera o store 'sgs-auth'); não toca em outras chaves — portanto 'sgs-last-email' sobrevive ao logout sem mudança no useAuth.
