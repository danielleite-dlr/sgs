## Spacing Scale

Declared values (base 4px system):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between icon and label |
| sm | 8px | Compact element spacing, input internal padding |
| md | 16px | Default element spacing, form field gaps |
| lg | 24px | Section padding, card internal padding |
| xl | 32px | Layout gaps between form sections |
| 2xl | 48px | Major section breaks, auth card vertical padding |
| 3xl | 64px | Page-level centering offsets |

Exceptions:
- Touch targets (buttons, links): minimum 44px height on mobile (WCAG 2.1 AA §2.5.5)
- Auth card max-width: 400px on desktop, full-width on mobile with 16px horizontal margin
- Auth page vertical centering: `min-h-screen flex items-center justify-center`

Source: PRD_Frontend §4.2.3

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (desktop) / 15px (mobile) | 400 (regular) | 1.5 | Form labels, paragraphs, helper text |
| Label | 14px | 500 (medium) | 1.4 | Input labels, secondary text, button labels |
| Heading | 20px | 600 (semibold) | 1.25 | Auth card titles (e.g., "Crie sua conta") |

Source: PRD_Frontend §4.2.2 — scale uses `--text-sm` through `--text-2xl`. Phase 1 uses `sm`, `base`, `xl`, `2xl` only.

## Color

All hex values from PRD_Frontend §4.2.1 CSS token definitions.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--color-background` → `--color-neutral-50` | `#FAFAF8` | Page background, auth page canvas |
| Secondary (30%) | `--color-surface` → `--color-neutral-0` | `#FFFFFF` | Auth card background, input backgrounds |
| Accent (10%) | `--color-primary-500` | `#5D54C7` | See reserved list below |
| Accent dark | `--color-primary-700` | `#3C3489` | Accent hover state only |
| Destructive | `--color-error-500` | `#D85A30` | Destructive actions only (see below) |
| Border | `--color-neutral-200` | `#E5E3DC` | Input borders, card borders, dividers |
| Text primary | `--color-text` → `--color-neutral-800` | `#2C2C2A` | All body and heading text |
| Text muted | `--color-text-muted` → `--color-neutral-500` | `#888780` | Helper text, placeholder text, step labels |
| Success | `--color-success-500` | `#1D9E75` | Email verification success state |
| Warning | `--color-warning-500` | `#EF9F27` | Not used in Phase 1 screens |

**Accent `#5D54C7` is reserved for:**
1. Primary submit button background (filled variant)
2. Hyperlinks (sign in / sign up / resend email links)
3. Focus ring on all interactive elements (`outline-color`)
4. Progress indicator in 2-step signup (active step dot)
5. "Email verificado" success icon fill

Accent is NOT used for: card borders, section headings, dividers, disabled states, secondary buttons (which use `border + neutral-800 text`).

**Destructive `#D85A30` is reserved for:**
- Field-level error message text
- Field border when in error state
- No destructive actions exist in Phase 1 screens beyond form errors

## Interaction Contracts

### 2-Step Signup Flow

- Step 1 fields validate on blur. Step 1 "Continuar" button is disabled until `nome`, `email`, and `senha` pass client-side validation.
- On "Continuar" click: validate Step 1 fields, check email uniqueness via API call. If unique, animate step transition (slide left, next step slides in from right). If email exists: show error inline, do not advance.
- Step 2 "Voltar" navigates back to Step 1 preserving Step 1 field values (do not clear).
- Step 2 "Criar conta" submits both steps as a single mutation. Loading state on button, button disabled during request.
- On success: redirect to `/verificar-email` with email displayed.

### Form Validation Timing

- Validate on blur (not on change) — prevents aggressive feedback while typing.
- Show error message below the field, text `text-sm text-error-500`.
- Input border changes to `border-error-500` on error state.
- On successful blur correction: border returns to default, error message disappears.
- Submit button: disabled until all required fields pass client-side validation.

### Loading States

- Submit buttons: show spinner (16px lucide `Loader2` with `animate-spin`) + loading copy. Button disabled during request.
- No full-page spinners on auth screens. No overlay.
- Resend email button: disabled for 60 seconds after click (countdown shown: "Aguardar 47s").

### Password Field

- Toggle visibility via `Eye` / `EyeOff` lucide icons inside the input (right side). `aria-label="Mostrar senha"` / `"Ocultar senha"`.
- No password strength meter in Phase 1 (deferred).

### Auth Error Display

- Errors returned from server appear as an inline alert above the submit button, not as a toast.
- Use shadcn `Alert` with `variant="destructive"` for auth-level errors (wrong credentials, expired token).
- Field-level validation errors appear below each field.
- Toast is used only for success states (email resent, invitation accepted).

### Focus Management

- On page load: auto-focus on first input field.
- On validation error after submit attempt: focus moves to first field with error.
- On step transition in signup: focus moves to first field of the new step.
- Invitation expired/used token states: no form shown, only error state card.

### Accessibility Constraints (WCAG 2.1 AA)

- All color combinations must pass 4.5:1 contrast ratio for normal text, 3:1 for large text (18px+).
- `#2C2C2A` text on `#FAFAF8` background: ~16:1 — passes.
- `#FFFFFF` on `#5D54C7` button: ~5.2:1 — passes.
- `#D85A30` error text on `#FFFFFF`: ~4.5:1 — passes (verify at implementation).
- All form inputs have explicit `<label>` elements associated via `htmlFor`.
- All icon-only buttons have `aria-label`.
- Error messages linked to their input via `aria-describedby`.
- Keyboard navigation: Tab order follows visual reading order. No keyboard traps.

- Position: centered above card heading.
- SGS wordmark or logomark — to be provided at implementation time. Use text "SGS" in `--color-primary-700` at 24px bold as placeholder.
- No background on logo area — sits on `--color-neutral-50` canvas.

```
Two dots (or "Passo X de 2" text)
Active step: --color-primary-500 filled dot, 8px
Inactive step: --color-neutral-200 filled dot, 8px
Gap between dots: 8px

```
