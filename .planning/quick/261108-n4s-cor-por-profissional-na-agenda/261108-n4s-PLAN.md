# Cor automática por profissional na agenda

<objective>
Cada profissional ganha automaticamente uma cor na agenda: o cartão do agendamento passa a ter
fundo claro (tint) na cor dela, na vista Dia e na vista Semana, e a bolinha com a inicial no
cabeçalho da coluna usa a mesma cor. A borda esquerda do cartão continua sendo a cor do status.
Sem migration, sem campo novo, sem opção no cadastro. Decisões travadas em 261108-n4s-CONTEXT.md.

nome completo — filtro da lateral, chips da barra e cabeçalho da coluna — nunca só pelas iniciais
nem com nome cortado.

Purpose: a usuária quer bater o olho na agenda e saber de quem é cada atendimento.
Output: helper de paleta + testes, cartões/cabeçalho/semana coloridos, nome completo nos pontos
da agenda, E2E novo e E2E de celular ajustado.

```ts
export interface ProfessionalTone {
  name: string;      // rótulo interno ("lilás", "verde"...), útil em teste/debug
  bg: string;        // fundo do cartão
  bgHover: string;   // fundo no hover (um passo mais escuro)
  avatarBg: string;  // bolinha da inicial no cabeçalho (texto neutral-800)
}
export const NEUTRAL_TONE: ProfessionalTone; // { bg '#FFFFFF', bgHover '#F9FAFB', avatarBg '#F5E6FB' } = visual de hoje
export const PROFESSIONAL_TONES: readonly ProfessionalTone[]; // 12 itens, ordem abaixo
export function buildProfessionalToneMap(ids: readonly string[]): Map<string, ProfessionalTone>;
```
Paleta (bg / bgHover / avatarBg), ordem pensada para vizinhas bem diferentes:
 1 lilás   #F3E8FF / #E9D5FF / #D8B4FE
 2 verde   #DCFCE7 / #BBF7D0 / #86EFAC
 3 azul    #DBEAFE / #BFDBFE / #93C5FD
 4 âmbar   #FEF3C7 / #FDE68A / #FCD34D
 5 rosa    #FFE4E6 / #FECDD3 / #FDA4AF
 6 turquesa#CCFBF1 / #99F6E4 / #5EEAD4
 7 laranja #FFEDD5 / #FED7AA / #FDBA74
 8 índigo  #E0E7FF / #C7D2FE / #A5B4FC
 9 lima    #ECFCCB / #D9F99D / #BEF264
10 fúcsia  #FAE8FF / #F5D0FE / #F0ABFC
11 ciano   #CFFAFE / #A5F3FC / #67E8F9
12 areia   #E7E5E4 / #D6D3D1 / #A8A29E
(São tons claros, longe dos tons escuros/saturados de STATUS_SPINE_COLORS; a borda de 3 px do
status continua legível. Se algum par falhar no teste de contraste, escurecer o texto ou clarear
o tom — o teste é a régua.)

Atribuição `buildProfessionalToneMap(ids)`: remove duplicados, ordena uma CÓPIA com comparação
de string simples (`a < b ? -1 : a > b ? 1 : 0`, não localeCompare), e dá
`PROFESSIONAL_TONES[i % 12]` pela posição. Sem hash (hash colide). Mesmo conjunto em qualquer
ordem → mesmo mapa.

Fonte da lista: TODOS os membros `isProfessional` do `MembersQuery` (antes do filtro `ownOnly`
e independente de `visibleProfIds`), para a cor não mudar ao filtrar nem entre Dia/Semana.
Observação para o SUMMARY: se para o papel PROFESSIONAL o `members` só devolver ela mesma, ela
verá o tom 1 na própria agenda (outra cor da que o gestor vê). Aceitável (cada usuária vê a
agenda de forma consistente); só registrar, não mexer no backend.

Fundo por variável CSS (para o hover funcionar): `getAppointmentStyle(appt, slotHeight, tone =
NEUTRAL_TONE)` deixa de devolver `backgroundColor` e devolve `"--appt-bg": tone.bg,
"--appt-bg-hover": tone.bgHover` (tipar como `CSSProperties & Record<"--appt-bg" |
"--appt-bg-hover", string>` ou cast documentado). No AppointmentCard trocar `bg-white
hover:bg-neutral-50` por `bg-[var(--appt-bg,#FFFFFF)] hover:bg-[var(--appt-bg-hover,#F9FAFB)]`
(fallback mantém o visual de hoje). WeekGrid usa as mesmas classes e variáveis.

`ScheduleProfessional` ganha `tone?: ProfessionalTone` (opcional, para não quebrar fixtures de
teste existentes). O campo `color` e `PROFESSIONAL_COLORS` ficam (categoryColor e fixtures usam);
SchedulePage passa a preencher `color: tone.bg` para manter o campo coerente.
