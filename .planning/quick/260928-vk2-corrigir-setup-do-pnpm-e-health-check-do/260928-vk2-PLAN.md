<jq_decision>
**Expressão escolhida: `jq -s 'flatten | ...'`** (slurp + flatten).

Por quê:
- `-s` (slurp) lê o stream inteiro e o embrulha em um array. Com JSON Lines isso produz `[obj, obj, ...]` — exatamente o que `.[]` / `map()` esperam.
- Se o runner tiver uma versão do Compose que ainda emite um array JSON, `-s` produz `[[obj, obj]]` (array aninhado); `flatten` desfaz o aninhamento e o resultado volta a ser `[obj, obj]`.
- `flatten` sobre um array de objetos é no-op (só achata arrays aninhados), então a mesma expressão serve aos dois formatos sem branch.
- Alternativa descartada: `jq -r 'select(...) | .Name' | wc -l` — funciona só com JSON Lines, quebra com array, e adiciona um processo a mais no pipe.

Validado localmente contra as duas fixtures: ambos os formatos retornam `total=2`, `healthy=1`, `running=2`. A expressão antiga reproduz exatamente `jq: error (at <stdin>:1): Cannot index string with string "Health"` com exit 5.
</jq_decision>

**2a — job `boot-time`, passo "Time docker compose up" (~L113-115).** Substituir as três expressões:

```bash
            total=$(docker compose ps --format json | jq '. | length')
            healthy=$(docker compose ps --format json | jq '[.[] | select(.Health == "healthy")] | length')
            started=$(docker compose ps --format json | jq '[.[] | select(.State == "running")] | length')
```

por:

```bash
            ps_json=$(docker compose ps --format json)
            total=$(printf '%s\n' "$ps_json" | jq -s 'flatten | length')
            healthy=$(printf '%s\n' "$ps_json" | jq -s 'flatten | map(select(.Health == "healthy")) | length')
            started=$(printf '%s\n' "$ps_json" | jq -s 'flatten | map(select(.State == "running")) | length')
```

Capturar a saída uma vez em `ps_json` evita três chamadas ao Compose por iteração e garante que os três contadores enxerguem o mesmo snapshot (hoje eles podem divergir entre si e fazer a condição `started = total` nunca casar).

Manter a lógica de decisão existente exatamente como está (`total > 0 && healthy > 0 && started = total`, limite de 300s, mensagens de FAIL, exit codes). Esta task corrige **parsing**, não semântica.
