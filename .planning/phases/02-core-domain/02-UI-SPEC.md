## Spacing Scale

Inherited from Phase 1. No new tokens. No exceptions beyond the existing WCAG touch target rule.

| Token | Value | Phase 2 Usage |
|-------|-------|--------------|
| xs | 4px | Icon-to-text gap in sidebar nav items, badge internal padding |
| sm | 8px | Table cell internal padding, badge margin, sidebar sub-item indent |
| md | 16px | Card internal padding (compact), form field gap, toolbar gap |
| lg | 24px | Sidebar padding, page header bottom margin, card internal padding (default) |
| xl | 32px | Page-level horizontal padding (desktop content area) |
| 2xl | 48px | Section breaks within a form (e.g., between pricing variant group and base fields) |
| 3xl | 64px | Not used in Phase 2 screens |

**Exceptions (carried from Phase 1):**
- Touch targets (buttons, links, row actions): minimum 44px height on mobile (WCAG 2.1 AA §2.5.5).
- Sidebar width: 240px (lg+), collapsed to icon-only at 64px (md), hidden on mobile (drawer mode).
- Content area: full viewport width minus sidebar; horizontal padding `xl` (32px) on desktop, `md` (16px) on mobile.

## Typography

Inherited from Phase 1. Exactly 4 sizes, 2 weights. No new sizes or weights are introduced in Phase 2.

| Role | Size | Weight | Line Height | Phase 2 Usage |
|------|------|--------|-------------|--------------|
| Label | 14px | 600 (semibold) | 1.4 | Table column headers, form labels, badge text, sidebar nav items, breadcrumb segments, tab labels, section sub-headings |
| Body | 16px | 400 (regular) | 1.5 | Table cell values, form helper text, card body text, empty state descriptions |
| Heading | 20px | 600 (semibold) | 1.25 | Page titles ("Serviços", "Clientes"), dialog headings, section headings within forms |
| Display | 24px | 600 (semibold) | 1.2 | Not used in Phase 2 (was for brand wordmark in auth) |

**Typography notes:**
- Table column headers: 14px weight 600, color `#888780` (text-muted) — visual hierarchy without competing with data.
- Table cell values: 16px weight 400, color `#2C2C2A`.
- Row action labels in DropdownMenu: 14px weight 400, color `#2C2C2A`.
- Sidebar nav items: 14px weight 600 when active, 14px weight 400 when inactive.
- Breadcrumb: 14px weight 400 for parent segments, weight 600 for current segment.
- Badge text: 14px weight 600 — matches label role.
- Price values in tables: 16px weight 600 (semibold) to distinguish monetary data at a glance.

## Interaction Contracts

### List Page Pattern (applies to all 6 catalog lists + clients list)

Every list page follows this layout:

```
PageHeader (title + CTA)
SearchBar + Filters row
Table (sortable columns, row hover, row actions)
Pagination footer
```

**Search bar:**
- shadcn Input with Search lucide icon left-inside
- Debounce: 300ms after last keystroke before query fires
- Placeholder specific to each entity (see Copywriting Contract)
- Width: 320px on desktop, full-width on mobile

**Table behavior:**
- Sortable columns: clicking header sorts ascending → descending → unsorted (cycle)
- Sort indicator: ChevronUp / ChevronDown lucide icon, 14px, inline with header label
- Row hover: `bg-neutral-50` transition 100ms
- Row click: navigates to detail/edit page (except for catalog entities that only have inline CRUD via Dialog/Sheet)
- Row actions: last column, DropdownMenu with `MoreHorizontal` lucide trigger (3-dot menu)
  - Trigger: ghost button 36px × 36px, visible only on row hover (or always on mobile)
  - Items: Edit (pen icon) → opens Dialog/Sheet; Delete (trash icon, destructive color) → AlertDialog

**Pagination:**
- Offset-based (not cursor): "1–20 de 47 resultados"
- Page size: 20 items default
- Controls: Previous / Next buttons + page number input
- Previous / Next: shadcn Button outline variant, 36px height
- Current page indicator: page number on `bg-primary-500 text-white` pill
- When total ≤ 20 items: pagination row hidden

**Loading state (list):**
- Show 5 Skeleton rows (Table rows with shimmer) while query is in-flight
- Skeleton: neutral-200 background, animated pulse, matching column layout

**Empty state (list, no data at all):**
- Centered vertically in table area
- lucide-react icon: 48px, color `#888780`
- Heading: 16px weight 600
- Body: 14px weight 400 color `#888780`
- CTA: primary button ("Criar primeiro X")
- See Copywriting Contract for per-entity copy

**Empty state (list, after filter/search with no results):**
- Same layout as above but different copy ("Nenhum resultado para "X"")
- No CTA button (don't offer to create when search is active)
- Link to clear search: "Limpar busca"

### Form Pattern (CRUD create + edit)

**Form shell:**
- Displayed in Dialog (desktop) or Sheet (mobile, slide from bottom) for catalog entities
- Client create/edit: dedicated page (`/clientes/novo`, `/clientes/:id/editar`) — not Dialog
- Max dialog width: 560px; Sheet: full width mobile

**Dialog structure:**
```
DialogHeader: Entity name + action ("Novo Serviço" / "Editar Serviço")
DialogContent: Form fields (scrollable if tall)
DialogFooter (sticky): [Cancelar] [Salvar]
```

**Form validation:**
- Validate on blur — not on change — to avoid aggressive feedback while typing
- Error message: below field, 14px weight 600 color `#D85A30`
- Error border: `border-error-500` on Input
- On blur correction: border returns to default, error disappears
- Required field indicator: asterisk `*` after label text (14px color `#D85A30`)
- "Cancelar" button: outline variant, closes Dialog without saving, no confirmation needed if form is pristine; if dirty, show brief confirm toast "Descartar alterações? [Sim] [Não]" — NOT an AlertDialog (low friction)

**Save behavior:**
- "Salvar" button: primary filled, disabled during request (spinner + loading copy)
- On success: Dialog/Sheet closes, list row updated or new row appears, Sonner toast success
- On server error: inline Alert above footer (shadcn Alert variant="destructive"), Dialog stays open

**Reorder (categories and services within category):**
- Up / Down buttons (ChevronUp / ChevronDown lucide) in the `display_order` column of the list
- Buttons disabled at extremes (first item has no Up, last has no Down)
- Optimistic update: move row visually immediately, patch mutation fires in background
- On mutation error: revert order + Sonner error toast

### Package Pricing Transparency (D-09)

In the package form and package list detail view, always show:
```
Soma individual: R$ 280,00
Preço do pacote: R$ 220,00  (economy of R$ 60,00)
```
- "Soma individual" computed client-side from selected services' base prices, updates live as services are added/removed
- "Preço do pacote" is the editable `package.price` field
- Both values in 16px weight 600
- If package price > individual sum: show "(R$ X acima do total individual)" in `warning.500` color
- If package price < individual sum: show "(R$ X de desconto)" in `success.500` color
- If equal: no supplementary text

### Stock Low Badge (D-15)

In the products list, for any row where `stock_quantity <= min_stock_level`:
- Inline badge in the "Estoque" column: `bg-error-500/10 text-error-500 border border-error-500/30 rounded-sm px-sm py-xs text-label`
- Badge text: `{quantity} {unit}` + `TriangleAlert` lucide icon 12px inline-left
- Normal stock: plain text value, no badge, no border

### Commission Rule Scope UX (D-17/D-18)

Commission rule form uses a scope-first flow:
1. Radio group: "Tipo de regra" — 5 options:
   - "Profissional + Serviço" (most specific)
   - "Serviço"
   - "Categoria"
   - "Produto"
   - "Padrão da organização" (default)
2. Based on selected scope, show conditional fields:
   - "Profissional + Serviço": show Member combobox + Service combobox
   - "Serviço": show Service combobox
   - "Categoria": show Category combobox
   - "Produto": show Product combobox
   - "Padrão": no additional scope fields
3. Then always show: Commission type (`kind`) radio — "Valor fixo (R$)" / "Percentual (%)" — and `value` numeric input

### CPF Duplicate Alert (D-22)

In the client create/edit form, on blur of CPF field:
1. If CPF field is blank: skip — CPF is optional (D-21)
2. If CPF is invalid (fails checksum): show field-level error "CPF inválido" — do not query
3. If CPF is valid: fire GraphQL query `clientsByField(cpf: "...")` (debounced, 500ms)
4. If matches found: render Alert above the "Salvar" / form footer area:
   ```
   ⚠️  CPF já cadastrado para outro(s) cliente(s):
   • Ana Silva — (11) 99999-9999  [Usar este cliente]
   • Ana M. Silva — (21) 88888-8888  [Usar este cliente]
   Ou continue para criar um novo cliente.
   ```
   - Alert: `variant="warning"` — amber border-left, `#EF9F27/15` background
   - Each existing client name is a link (primary color) navigating to that client's detail
   - "[Usar este cliente]" link = navigate to existing client detail, discarding current form
   - Alert stays visible; "Salvar" button remains enabled — attendant decides
5. No duplicate check for email/phone in Phase 2 (D-22 scopes to CPF only per implementation decisions)

### Image Placeholder (D-25)

Where `cover_image_url` would display (category, service, product list):
- 40px × 40px square with `border-radius: 8px` (md)
- Background: `primary.50` (#EEEDFE)
- Content: uppercase initials of the entity name (max 2 chars), 14px weight 600, color `primary.700` (#3C3489)
- If name is numeric or special chars only: use relevant lucide icon instead (Scissors for service, Package for product, Folder for category)

### Soft-Delete Confirmation (D-26)

All catalog entities and clients use soft-delete, not hard delete. The confirmation copy reflects this.

Flow:
1. User clicks "Excluir" in row DropdownMenu
2. AlertDialog appears:
   ```
   Desativar [Nome da entidade]?
   
   [Entity name] ficará inativo e não aparecerá em novos agendamentos,
   mas o histórico e relatórios serão preservados.
   
   [Cancelar]  [Desativar]
   ```
3. AlertDialog "Desativar" button: `variant="destructive"`
4. On confirm: soft-delete mutation fires, row disappears from list (filtered by `deleted_at IS NULL`)
5. Sonner toast: "[Nome] desativado. [Desfazer]" — Undo fires `restoreEntity` mutation if clicked within 5 seconds

## Accessibility Constraints (WCAG 2.1 AA — Phase 2)

All Phase 1 accessibility rules apply. Phase 2 additions:

- Sidebar nav items: `role="navigation"`, `aria-label="Navegação principal"`. Active item: `aria-current="page"`.
- Collapsible Catálogo section: `aria-expanded`, toggle with keyboard (Enter/Space).
- Tables: `<thead>` with `scope="col"`, sortable headers have `aria-sort="ascending|descending|none"`.
- Dialogs/Sheets: focus trap active, `aria-labelledby` pointing to DialogTitle, `aria-describedby` for DialogDescription.
- AlertDialog: focus moves to "Cancelar" on open (safer default for destructive actions).
- Tabs: `role="tablist"`, `role="tab"`, `role="tabpanel"`, arrow key navigation.
- DropdownMenu: `aria-haspopup="menu"`, keyboard-navigable.
- Badge (low stock): `aria-label="Estoque baixo: {quantity} {unit}"` for screen readers.
- CPF Input with mask: `aria-label="CPF"`, `inputmode="numeric"`, `autocomplete="off"`.
- Price inputs: `aria-label` includes currency context (e.g., "Preço base em reais").
- All color contrast: inherited Phase 1 token choices pass 4.5:1 for normal text, 3:1 for large text.
- `#888780` on `#FFFFFF`: 3.1:1 — used only for 14px weight 600 (large text threshold). Do not use `#888780` at 14px weight 400 on white backgrounds in critical content.

**Icon-only elements — mandatory aria-labels:**

| Element | Location | `aria-label` value | Additional |
|---------|----------|--------------------|------------|
| Bell icon (BellIcon lucide) | Mobile header | `"Notificações (em breve)"` | `aria-disabled="true"` |
| Reorder Up button (ChevronUp lucide) | Category/service list order column | `"Mover {nome} para cima"` | `disabled` when first item |
| Reorder Down button (ChevronDown lucide) | Category/service list order column | `"Mover {nome} para baixo"` | `disabled` when last item |
| Pricing variant delete (TrashIcon lucide) | PricingVariantsEditor row | `"Remover variante"` | `aria-label` must include row context if multiple variants visible simultaneously |
| Low-stock warning icon (TriangleAlert lucide) | Sidebar "Produtos" nav item | `"Estoque baixo: {N} produto(s)"` | Paired with Tooltip for sighted users |
