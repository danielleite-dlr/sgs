## Decisions Made

- **Date formatting via `Intl.DateTimeFormat` instead of `date-fns`.** The plan text said "como o resto do app," but `date-fns` is not actually an installed dependency anywhere in `apps/frontend` (only listed in the decided stack in `CLAUDE.md`). Adding it would require editing the workspace-root `pnpm-lock.yaml`, which sits outside `apps/frontend/` — a hard boundary for this plan given the backend wave running in parallel in the same repo. `Intl.DateTimeFormat('pt-BR', {...})` covers the same formatting need (`blockingAppointments.startsAt`, invitation `expiresAt`) with zero new dependencies.
- **`InviteMemberDialog` uses only `cache.evict`, no `refetchQueries`.** The plan's action text for Task 2 only mentions eviction for `pendingInvitations`; keeping all three dialogs on the same cache strategy (evict + gc, no refetch) avoids a mixed pattern within one feature.
- **`aria-label` added to every `SelectTrigger`.** Not explicitly requested by the plan, but `FormControl`'s `Slot` injects `id`/`aria-describedby` onto the immediate child (`<Select>` Root, which renders no DOM node), so the `FormLabel`'s `htmlFor` doesn't reach the trigger button the way it does for plain `<Input>` fields. Explicit `aria-label` keeps the trigger accessible and gives tests a stable `getByRole('combobox', { name })` query, consistent with WCAG 2.1 AA in `CLAUDE.md`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] jsdom has no `PointerEvent`, so Radix Select/DropdownMenu never open under plain `fireEvent.click`/`fireEvent.pointerDown`**
- **Found during:** Task 2 (writing `member-dialogs.test.tsx`) and Task 3 (writing `profissionais-page.test.tsx`)
- **Issue:** Radix's `SelectTrigger`/`DropdownMenuTrigger` gate opening on `event.button === 0` inside their `onPointerDown` handler. `fireEvent.pointerDown` in Testing Library falls back to a plain `Event` (jsdom has no `PointerEvent` constructor), which silently drops the `button`/`ctrlKey` init properties, so the check never passes and the menu/listbox never opens — no test in the repo had exercised these primitives before this plan.
- **Fix:** Added `hasPointerCapture`/`setPointerCapture`/`releasePointerCapture`/`scrollIntoView` polyfills to `test-setup.ts` (defensive, used by Radix internals) and, where an actual open+select interaction is needed, construct the `pointerdown` event by hand with `Object.defineProperty(event, 'button', { value: 0 })` before dispatching via `fireEvent(el, event)`. `SelectTrigger`'s own `onClick` fallback (fires when `pointerType !== 'mouse'`, default `'touch'`) meant plain `fireEvent.click` was already sufficient to open `Select` — only `DropdownMenuTrigger`, which has no `onClick` handler at all, needed the hand-built event.
- **Files modified:** `apps/frontend/src/test-setup.ts`, `apps/frontend/src/pages/__tests__/profissionais-page.test.tsx`
- **Verification:** All 13 `member-dialogs.test.tsx` tests and all 6 `profissionais-page.test.tsx` tests pass, including role-select interactions and the dropdown-menu open/Desativar-vs-Reativar assertions.
- **Committed in:** `6b0b441` (test-setup.ts, part of Task 2), `18e484c` (profissionais-page.test.tsx, part of Task 3)

**2. [Rule 1 - Bug] `Select` "changing from uncontrolled to controlled" React warning**
- **Found during:** Task 2, first full test run
- **Issue:** `InviteMemberDialog`'s `roleName`/`seniorityTier` fields started as `undefined` (no default selection) and became a string after a value was picked, which Radix's `Select` (a controlled component) surfaces as a React warning about switching controlled/uncontrolled.
- **Fix:** Default these fields to `''` instead of `undefined`, and pass `value={field.value ?? ''}` everywhere a Select's value can be absent — consistent with the existing `CommissionRuleForm` category picker pattern.
- **Files modified:** `apps/frontend/src/features/identity/components/InviteMemberDialog.tsx`, `apps/frontend/src/features/identity/components/MemberEditDialog.tsx`
- **Verification:** Console warning gone on rerun; all tests still green.
- **Committed in:** `6b0b441` (part of Task 2)
